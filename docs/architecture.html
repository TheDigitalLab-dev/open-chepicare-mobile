Flujos de Datos Principales
🔐 Flujo de Autenticación
1
Usuario envía credenciales desde LoginForm → Auth API client
2
AuthController#login llama Auth::Login action → valida email/password
3
Result.success(user:) → tokens JWT guardados como httpOnly cookies
4
Middleware de Inertia decodifica JWT en cada request → establece @current_user
5
currentUser compartido como prop de Inertia a todos los componentes React
6
useAuth hook → dispatcha a authSlice → redirect al dashboard
🐾 Flujo: Gestión de Mascotas
1
Owner completa PetForm con datos de la mascota
2
usePets hook llama Pets API client → POST /pets con wrapper { pet: {...} }
3
PetsController llama Pets::CreatePet action → valida y guarda
4
Result.success(pet:) → controller responde con JSON { pet: {...} }
5
petsSlice actualizado en Redux → UI re-renderiza con nueva mascota
6
Foto: endpoint separado POST /pets/:id/photo con FormData → ActiveStorage
📅 Flujo: Reserva de Cita
1
Owner selecciona servicio → useMyAppointments consulta vets disponibles
2
OwnerAvailabilityController → OwnerPortal::Appointments::GetAvailableVets + Days
3
Owner selecciona fecha/hora y confirma el OwnerAppointmentForm
4
OwnerPortal::Appointments::CreateAppointment valida slot → crea Appointment
5
Se genera automáticamente un Payment en estado "pending"
6
Admin puede confirmar/cancelar/completar desde admin/appointments
⚕️ Flujo: Historia Clínica
1
Vet crea consulta desde admin/consultations usando ConsultationViewer
2
Admin::Medical::CreateConsultation guarda con diagnóstico y tratamiento
3
Desde consulta se agregan: Prescriptions, LabExams, Vaccinations
4
Owner puede ver y completar items de prescripción desde su portal
5
Reporte médico generado por Admin::Medical::GenerateReport → cachea en DB
6
Admin::Medical::ExportPdfReport genera PDF descargable o envío por email
💳 Flujo: Gestión de Pagos
1
Payment se crea automáticamente al confirmar una cita
2
Payment tiene PaymentItems con servicios y productos detallados
3
Estado: pending → paid (register) o cancelled o extended (due_date)
4
Owner registra pago desde portal → Payments::RegisterPayment action
5
Admin puede crear Refunds vinculados al pago original
6
Balance calculado por Admin::Financial::GetBalance → cacheado en MetricsSnapshot
📊 Flujo: Métricas & Analytics
1
Admin abre admin/metrics → useMetrics hook solicita datos
2
Metrics API client → GET /admin/metrics/dashboard
3
Admin::MetricsController busca en metrics_snapshots (caché)
4
Si no hay caché → Admin::Metrics::CalculateDashboard agrega datos
5
Resultado guardado en metrics_snapshots con timestamp
6
metricsSlice actualizado → MetricCard + MetricsChart muestran datos
